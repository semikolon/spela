# spela — AI-Agent-Ready Media Controller

## NO PERSONAL DATA (MANDATORY)

## Overview

Rust CLI + HTTP API server for torrent-to-Chromecast streaming. Single 5.2MB binary, zero runtime deps on target (ffmpeg only; BitTorrent client is embedded via librqbit since v3.3.0).

**Status**: v3.22 LIVE on Darwin (`darwin.home:7890`). Single Rust binary; ffmpeg the only runtime dep (BitTorrent embedded via librqbit).

**Current capabilities**: torrent → Chromecast / VLC / in-browser / Shannon streaming, driven by the web remote (`/remote`) + a thin CLI + a direct HTTP API. HLS transcode (HEVC→H.264 NVENC for Chromecast; HEVC pass-through for browsers; original-language audio — never a dub); **5-tier Sarpetorp-tuned ranker** (target-scoped codec preference); Smart Resume + per-episode HWM; self-healing disk cache; Local-Bypass of the on-disk library; alass subtitle-sync; source-racing on weak swarms; anti-poisoning blocklist. **Watch tracking (the TV-Time replacement)**: a unified `/home` queue (Continue → New Episodes → Coming Soon → Recommended; "Coming Soon" = caught-up followed shows with an upcoming episode, air-date-labelled from **TVmaze** with TMDB as the fallback — TMDB lags the real platform drop), a followed-shows new-episode tracker with non-linear seen-seasons, the watch-ledger as the single source of truth for BOTH progress (survives unfollow) and seen-status (`has_seen`; a series counts as watched only past 3 distinct episodes, and a mis-mark is undoable via `/watched-remove`), and an arsenal-and-harness recommender (Claude writes `recommendations.json`; picks are seen-filtered at read time). **Open-in-VLC** with a web-remote control now-view relayed via the Mac-side `spela-vlc-bridge`; the VLC path now carries the FULL dead-source kit the Chromecast path had (proven-complete Local Bypass · bounded metadata wait · stall gate · source racing · rotation) — a NEW play target inherits none of it automatically, so audit any future one against all five. **Series carry a status badge** (Returning / Renewal undecided / Ended / Cancelled, merged from TMDB+TVmaze) plus a **dated one-line intel note** written by Claude via `POST /show-notes` — pull, not push, so a note is as current as its last refresh and the UI surfaces that date once stale. **VLC is the DEFAULT play target** (the Mac monitor is the main watch surface now); library titles open in VLC via the SAME shared target dispatch (`playToTarget`) as torrent plays (`/library/vlc.m3u` resolves a library title to its serve-library URL for native VLC decode). **Nav is six views**: Home · Search · Library · Now · To Watch · **Rewatch** (the ledger as a browsable shelf — `has_seen` answers *is this a discovery?*, never *would he watch it tonight?*). **UI identity**: Manrope (embedded variable WOFF2, base 17px/500), section-header voice on the nav, and a hover gleam on every media item and control — see the Typography and Hover-gleam entries in Key Files.

**Graceful restart — LIVE (socket-activated, 2026-08-04).** systemd `spela.socket` holds both listeners (LAN IP + loopback, `FreeBind`) across a `spela.service` restart; spela inherits the fds via `listenfd` and stops accepting new connections on SIGTERM (`.with_graceful_shutdown`), so the socket stays bound the whole time and a redeploy no longer drops the port. **A LIVE stream is an effectively-infinite connection that cannot drain**, so a mid-watch restart waits out `TimeoutStopSec=10` then gets SIGKILLed — that is EXPECTED, not a bug (the journal's `stop-sigterm timed out, Killing` line is normal); RECONNECTION, not draining, is what carries a live stream across the ~1s gap. **Resume by stream type**: Chromecast auto-resumes via boot-resume (`maybe_resume_stream_on_boot` re-establishes transcode+cast from the persisted `CurrentStream`; Chromecast-scoped + recency-guarded + `SPELA_NO_RESUME` kill-switch); browser hls.js + VLC self-recover on reconnect — `handle_vlc_stream` re-resolves the result id from persisted `last_search` + re-adds the torrent ON-DEMAND (no `CurrentStream` needed), and the `vlc://` handler passes `--http-reconnect` so VLC resumes the byte-range from its last offset (spela serves Range). **So VLC is NOT the weak restart case — it self-heals.** Units live in the Darwin hemma overlay + `/etc` (`systemctl enable spela.socket`). **SPA served from disk** (`handle_remote_html` reads `CARGO_MANIFEST_DIR/static/remote.html`, embedded `include_str!` fallback) so a frontend edit goes live on the next Darwin `git pull` with NO `cargo build` or restart. **VLC reconnect-across-restart is verified live** (2026-08-04: after a real restart, VLC re-requested a mid-file byte-range and resumed in place — even on the pre-`--http-reconnect` handler, via VLC's own resume-on-disconnect). The one remaining owed live-verify is the Chromecast boot-resume path (a cast re-establishing itself across a restart).

**Operational detail lives in the Key Files + Hard-Won Lessons sections below; the current-vs-desired gotchas + the audio-drop root cause are in Hard-Won Lessons. Version-by-version history is in `git log` (each vX.Y maps to its commits) — this Status is deliberately NOT a changelog (that chronicling belongs in git, per the documentation philosophy).**

**Architecture**: `spela server` on Darwin (`darwin.home:7890`). `spela <command>` thin HTTP client from any LAN machine. Voice assistants call HTTP API directly.

## Usage

```bash
spela search "Good Luck Have Fun Dont Die"       # Auto-detects movie vs TV
spela search "legion" --season 1 --episode 5   # Search + rank results
spela play 1                                     # Play result #1 (auto: magnet, file_index, metadata)
spela play 1 --cast "Vardagsrum"                 # Play to living room TV
spela play 1 --no-intro                          # Skip intro bumper
spela next                                       # Next episode
spela pause / resume / stop                      # Playback control
spela status / history / targets                 # Info
```

`spela play <N>` is the primary flow. Carries all metadata (file_index, IMDB, show, season, episode) automatically from the last search.

- **Trailer on the search card (2026-08-27)**: `title_meta` returns `trailer_key` from TMDB `/videos` for the already-resolved `(kind, id)` — preference **official Trailer > unofficial Trailer > Teaser, YouTube only** (a teaser does not answer "do I want to watch this", which is the point of showing it); best-effort, any failure omits the affordance. The embed is a **click-to-load FACADE** (YouTube's own still + a play glyph; the `youtube-nocookie` iframe is created ONLY on click) — an eager iframe per search result would pull megabytes of third-party JS and set cookies, undoing the viewport-gated enrichment. **A playing trailer MUST NOT survive navigation**: hash routing only toggles `.view.on` and unmounts nothing, so a trailer kept playing audio over every other page until the tab closed (startling, at night). `stopTrailers()` blanks the `src` and REMOVES the node — removal is the only reliable stop, since a postMessage pause needs the YouTube iframe API and a visibility handler would not survive a re-render — and it is called from **`route()`** (the single choke point every navigation passes) plus `runSearch()`. **Any future embedded media must hook the same choke point.**

- **Hover gleam — TWO forms, chosen by the control's own shape (ruling 2026-08-28; full convention + rationale in `docs/ux_principles_media_remote_2026_07_04.md` § 8.1)**: boxed controls (background/border/radius) get the BOX gleam; **bare-text controls (no bg, no border — `.src-toggle`) get a TEXT gleam** (`background-clip:text` sweep across the glyphs) and NO box treatment. Applying the box form to bare text draws a glowing rectangle around nothing; rounding it was proposed and REJECTED, because a bare-text control must not acquire button chrome on hover. Text form needs EXPLICIT colours, never `currentColor` (the sweep sets `-webkit-text-fill-color:transparent`, which would resolve `currentColor` to transparent and erase the text). Original port detail: **Hover gleam (2026-08-26)**: ported from **brf-auto's dashboard queue-card refresh swoosh** (`~/Projects/brf-auto/frontend/src/index.css` → `.queue-card-swoosh`) — a 120° white gradient `translateX(-120% → 120%)` over `1.1s ease-out`. Two deliberate deltas from the source: **(1) intensity** — brf-auto peaks at `rgba(255,255,255,.7)` calibrated for a LIGHT cream card; over spela's near-black chrome (`#1f1f29` items) that reads as a camera flash, so the peak is re-scaled to **`--gleam-peak:.18`** (one knob at `:root`, every surface follows; residual glow is `--gleam-rest:.15`). **(2) trigger** — brf-auto fires once on a data refresh; here it fires on **hover** and then SETTLES into a persistent `box-shadow:inset 0 0 14px rgba(255,255,255,.15)`. The glow **rises across the WHOLE 1.1s sweep** (`transition:box-shadow 1.1s` on the `:hover` rule, no delay — an earlier build delayed it to `.5s` so it arrived as the gleam exited; Fredrik asked for it to fade in from the start). **Release stays quick**: the base rule's `.25s` applies on pointer-out, so the glow never lingers. **The rim never brightens**: an inset shadow paints INSIDE the border box, so each element keeps its own border colour (verified: hovered vs resting `borderTopColor` identical). **Pointer-only, wrapped in `@media (hover:hover)`** — iOS strands `:hover` after a tap, which would leave the glow burned onto the last-tapped row; touch keeps the `:active` feedback from the 2026-05-18 touch-target pass. Applied via a **CSS selector list, NOT a JS-applied class**, so dynamically rendered rows are covered with zero JS. Covered: `.fotap .src .card` (media items) + `.foplay .fomark .founfollow .foseasonbtn .unmark .playicon .srcbtn .tgt .tbtn .topt .newbadge` + `nav a` + `.seg button .toast button .banner button`. Deliberately EXCLUDED: `.brand` and `.twhead` (bare text, no box for an inset glow to live in) and the `.foitem`/`.wrow` layout wrappers (transparent, zero-border — their children carry the effect, and gleaming both would double-fire on one hover). **Exempt: `#v-search .card`** — the search view usually holds ONE result, so the card IS the page and gleaming it on any pointer move is noise; its inner controls (`.playicon .markw .followbtn .rtlink .src-toggle`) keep the effect, and the scoping to `#v-search` leaves the LIBRARY grid (same `.card` class, many cards) untouched. **`nav a` needs `white-space:nowrap`** — the uppercase + `.09em` tracking widened the labels enough that TO WATCH wrapped to two lines in a narrow window. **Coverage is audited, not assumed**: walking every rendered `button`/`a[href]` per view against the selector list found four search-card buttons that had been missed entirely. **Testing gotcha**: pausing a `spelaGleam` animation from DevTools (`anim.pause()`) leaves the sweep frozen mid-pill and the glow stuck ON that element — it survives hash navigation and reads exactly like a styling bug ("why is NOW highlighted?"). It is a test artifact; a full reload clears it. Check `el.getAnimations()` for a `paused` entry before diagnosing. **Measurement gotcha**: the translated `::after` inflates the host's `scrollWidth` (a `.fotap` reads 2876 vs a 1307 `clientWidth`), so a naive `scrollWidth > clientWidth` overflow audit reports false clipping — disable the pseudo and `scrollWidth` drops to exactly `clientWidth`. Nothing is actually clipped; `overflow:hidden` is required for the sweep and was verified safe (no descendant escapes its box on any view).

## Build & Deploy

```bash
# Repo cloned on Darwin at ~/Projects/spela (Rust 1.94):
cd ~/Projects/spela && git push   # from Mac
ssh darwin 'cd ~/Projects/spela && git pull && nice -n19 cargo build --release'   # nice: see ⚠ below
ssh darwin 'sudo systemctl restart spela'
```

**⚠ ALWAYS low-priority the Darwin `cargo build` — it shares 4 cores with latency-sensitive services (2026-07-29 rule).** Darwin co-hosts the **single-slot `llama-embeddings` server** (`192.168.4.1:8080`, `--embedding`, NO `--parallel` — it serializes ALL consumers: mannaminne semantic search, Ruby, Graphiti) plus Graphiti-SSE (:8500), AdGuard DNS, and the router. A full `cargo build --release` spikes the 4-core box to load ~7 and starves them — a spela rebuild on 2026-07-29 timed out mannaminne's semantic layer for ~an hour. So `nice -n19 cargo build --release` (above) or `systemd-run --scope -p CPUWeight=idle cargo build --release`. Belt-and-suspenders on the embedder side: a systemd drop-in gives it `Nice=-10`/`CPUWeight=10000` (dotfiles `f424ee83`), but nice-ing the build is the courtesy that keeps DNS/embedder tail-latency clean. (An in-flight *transcode* is unaffected by a build — segments serve from disk — but the EMBEDDER is, so nice the build regardless of whether a stream is live.)

`~/.local/bin/spela` on Darwin is a symlink to `~/Projects/spela/target/release/spela` (verified Apr 30, 2026 — `lrwxrwxrwx ... -> /home/fredrik/Projects/spela/target/release/spela`). `cargo build --release` rewrites the inode the symlink points at; the running spela process keeps the OLD inode open until `systemctl restart` re-execs against the symlink. **No `cp` step needed** — earlier versions of this doc had `cp ~/Projects/spela/target/release/spela ~/.local/bin/` which errors with "are the same file" (Apr 30 deploy hit this).

**Build while the user is watching — compile freely, HOLD the restart (2026-07-04 operational rule)**: because the running spela keeps the OLD inode until `systemctl restart`, you can `git pull && cargo build --release` new code on Darwin *while a stream is live* with **zero interruption** — the build only stages the new binary at `target/release/spela`; nothing swaps into the running process until a restart. So during an active watch: **write + compile + commit freely; NEVER `systemctl restart spela`** (that kills the live cast) until the user confirms they're done watching. Any verification that needs a restart + a test-cast (e.g. the intro-warmup swap, or any cast-path change) waits for the user. A `cargo build` briefly competes for CPU with an in-flight transcode, but the transcode races ahead of playback and segments serve from disk, so the live stream is unaffected — BUT `nice -n19` the build regardless (MANDATORY for the co-hosted single-slot embedder, see the ⚠ above — not just paranoia). This makes "do unattended spela coding while I watch something" a first-class workflow — the only gated step is the restart-and-verify at the end.

**Running a SECOND isolated test instance on Darwin (test streams without touching production)** — for unattended barrage/latency/health testing while production (7890/Vardagsrum) stays live. Launch:
```bash
source ~/.secrets/tier-servers.env   # 2026-07-14: TMDB_API_KEY + MDBLIST_API_KEY now come from the age-encrypted tier-servers, sourced in prod's unit ExecStart (canonical fleet pattern, cf. sluss-web) — NOT inline Environment= anymore
```

Four collisions the env-flags avoid (each cost a failed launch when discovering this): **(1)** `SPELA_EPHEMERAL_DHT=1` — the persistent DHT reloads its stored `listen_addr` from the shared `~/.cache/com.rqbit.dht/dht.json` and tries to bind production's UDP port ("librqbit engine bootstrap failed"). This flag keeps DHT ON but skips persistence → librqbit binds an ephemeral OS-assigned port → REAL peer discovery, zero collision. (Do NOT use `SPELA_DISABLE_DHT` for latency testing — trackers-only starves peer discovery: an 859-seed torrent saw 1 peer at t=3s, inflating every measurement.) **(2)** `--port 7891` — the CLI `--port` (main.rs, default 7890) OVERRIDES `config.port`, so the `SPELA_PORT` env is dead; the loopback dual-bind also keys off it, else it fights prod's `127.0.0.1:7890`. **(3)** `SPELA_STATE_DIR`/`SPELA_MEDIA_DIR` — separate state.json + downloads (config.rs env overrides; there is NO `--state-dir`/`--media-dir` CLI arg). **(4)** `TMDB_API_KEY` (+ `MDBLIST_API_KEY` for RT scores) — shared `~/.config/spela/config.toml` has NO key; prod sources them from the age-encrypted `~/.secrets/tier-servers.env` (2026-07-14), so a test instance must `source` that file (above) or search 403s / RT is silent.
**⚠ Kill the test instance ONLY by its port — NEVER `pkill -f`.** Production's ExecStart is literally `spela server --host 192.168.4.1` (IDENTICAL command line; the distinguishing `--port`/env aren't in the pkill-matchable args), so `pkill -f "spela server"` KILLS PRODUCTION. Use `fuser -k 7891/tcp`. Always pass explicit `cast_name` (e.g. `"Fredriks TV"`) on every test `/play` — never rely on the shared `default_device`, which may be Vardagsrum (the user's live TV).

**Darwin working-tree drift recovery** (May 13, 2026, observed mid-deploy): if `git pull` fails on Darwin with *"cannot pull with rebase: You have unstaged changes"* AND `git diff --stat HEAD` shows ≥1000 LOC across multiple source files, do NOT `git stash`, do NOT force-discard. The likely cause is past-session edits made directly on Darwin (incident-debug hotpatches) that were later committed FROM Mac Mini, leaving Darwin's working tree dirty against an older HEAD pointer. Forensic procedure: (1) `git rev-parse HEAD origin/master` on Darwin to find Darwin's HEAD; (2) on Mac Mini, `git log --oneline <darwin-HEAD>..HEAD` to enumerate the commits Darwin doesn't have yet; (3) `sha1sum` each Darwin WT file against `git show <candidate-commit>:<file>` on Mac Mini for the same path — match means the WT content is byte-identical to a master commit, safe to discard. If all files match (or match + formatting-only deltas), `git checkout -- <files>` on Darwin is non-destructive — content is preserved in master. If even one file shows unique content, STOP and propose committing-from-Darwin to a branch instead. May 13 anchor: 8 files changed on Darwin, 7 matched `ab9a9a5` byte-for-byte, 1 (`search.rs`) was an older snapshot superseded by a `cargo fmt` pass on Mac — all features preserved in master, safe discard, deploy completed cleanly.

## Hard-Won Lessons (preemptive architecture gotchas — read before touching these areas)

Incident narratives + RCA + journal evidence: `git log` (every fix-commit carries the detailed analysis). Key SHAs: `7cd71c6` v3.4.0 bad-source trio · `c3b41a0` v3.4.1 ranker transitivity · `e0e81bf` v3.4.2 pause-gate · `e3960aa` v3.4.3 seek semantics · `40d3b96` v3.5.0 cache foundation · `ee38f92` 10-bit NVENC · `dcbaed7` CORS revert · `2c598f4` dual-bind · `245bef0` v3.8.0 serve-library drive-aware daemon. Deep dives: `docs/INCIDENT_REPORT_WILDERPEOPLE_2026_05_01.md`, `docs/CAST_DEBUGGING_RECIPES.md`.

**Playing on the PHONE: four independent bugs, all reproduced live on the iPhone 2026-08-31 — and the browser path was fine all along.** Symptom was "Star City just buffers forever on my phone"; The Diplomat played correctly on the same phone minutes apart, which is the discriminator that cracks it (H.264 → NVENC → `.ts` → padded, vs x265 → pass-through → `.m4s` → NOT padded). **(1) The live-edge stall — the actual endless buffering.** The fMP4 pass-through playlist was exempt from VOD-padding, so it carried no ENDLIST and no PLAYLIST-TYPE, which per the HLS spec means LIVE → a player starts ~3 target-durations from the END. Survivable only because the SPA's hls.js sets `startPosition:0` — **and iOS NEVER RUNS hls.js**: `canPlayType("application/vnd.apple.mpegurl")` is truthy in Safari/CriOS, so `attachPhoneVideo` takes the native branch and AVPlayer honours LIVE semantics (the player even labels it "Live Broadcast"). Signature in the kamal-proxy log: the phone fetched `seg_00021`…`seg_00027`, then re-polled `playlist.m3u8` every ~5-10 s **forever without requesting another segment**. The exemption existed only because the padder hardcoded a `.ts` placeholder extension; it now DERIVES the extension from the emitted entries, falling back to the `#EXT-X-MAP` header when no segment exists yet. **Do NOT reintroduce an fMP4 exemption.** Generic lesson: *a mitigation that lives in one client library is not a fix — it is a fix for that client*; the pass-through was validated against desktop hls.js only, on the one platform the user never uses. **(2) Wrong episode.** `find_local_bypass_match` has had episode-strictness since 2026-08-23, but never saw an episode: deriving the episode-bearing title was gated on `req.title.is_none()`, and the web remote ALWAYS sends a title (`d.show.title`, episode stripped) — so a request for S01E02 played the S01E01 file on disk. Now `choose_bypass_title` upgrades a caller title only when it does not already name an episode (a caller title is a DISPLAY label; the matcher needs an IDENTITY). **(3) Default target was VLC on every device** — see the `defaultTarget()` entry above. **(4) The target picker was OFF-SCREEN on a phone** and this is what made (3) unrecoverable rather than merely wrong: measured `#tgtBtn` at x=457 right=500 against a 393px viewport, with `html{overflow-x:clip}` making it unscrollable-to — the fix for the wrong default lived behind a button that could not be reached. Six icon-only nav tabs (278px) + brand + badge no longer fit one row, and the tabs are already at the 46px touch floor, so the header now WRAPS under 560px (brand + badge + chip on row one, nav full-width on row two). **Diagnostic note: two independent oracles agreed the previous night's attempts never reached spela at all** (spela's journal AND kamal-proxy's access log both empty for the whole evening) — reach for the proxy log, it records what the app's own log cannot.

**The Now-view clears itself when VLC quits, and returns you to where the play started (2026-09-05)**: quitting VLC left the remote showing the episode as playing until someone pressed Stop on a player that had already exited. The old refusal to auto-clear was CORRECT for the signal it had — `vlc_active` is byte-fetch freshness, and a VLC that buffers ahead goes quiet while still playing, so clearing on it would have fired mid-episode. The bridge polls **VLC's OWN http interface**, so a quit VLC is connection-refused: unambiguous, and a different signal entirely. Bridge → after `GONE_CONFIRM_TICKS`(3) probes `GONE_CONFIRM_INTERVAL`(2s) apart with no VLC, and ONLY while holding spela's sticky identity (which is what keeps a SECOND machine's bridge from reporting someone else's stream, and keeps an idle VLC silent), `POST /vlc/gone` once. Server → `LivePosition.gone` (title-guarded) + **stops the torrent**, which nothing did before: `reap_previous_vlc_torrents` fires only on the NEXT play, so a finished episode left a torrent running indefinitely. Remote → `pollVlc` sees `gone` on `/api/position`, runs `vlcEnded()`, returns via `leaveNowViewAfterStop()`. **Clears whether or not the episode finished** (Fredrik's ruling): if VLC is gone nothing is playing, so the view is false either way, and quitting halfway is when a stale now-playing misleads most; completion still decides watched-marking through the latch, and the resume point stays in the Continue rail. **Return-to-previous, not to a fixed page**: `goNowView()` records the view a play navigated FROM; home is only the fallback when there is none (opened cold on `#/now`, or reloaded). Manual navigation to Now (nav tab, now-bar) CLEARS it — choosing Now as a destination leaves nothing to return from. The pre-existing guard stands: none of it fires unless the user is actually on the Now-view. ⚠ **A bridge change needs trigger `42-restart-spela-vlc-bridge` to take effect** — `30-reload-launchagents` hashes PLIST content, so editing the script an agent RUNS restarted nothing and a new bridge sat inert until reboot (weeks, on a travel Mac).

**A VLC URL is pinned to the RELEASE, not to a position (2026-09-05)**: result ids are positional against a single mutable `last_search`, so ANY new search — the remote, another device, a diagnostic — silently repointed every in-flight `/vlc/{id}/…` URL, and VLC re-requests that exact URL on every reconnect and seek (`--http-reconnect`). Observed: while an episode played from `/vlc/4/`, searches in the same minutes moved id 4 from a 4.88 GB release to a 2.36 GB one, visible in the log as the expected size changing under a live stream; playback survived only because Local Bypass matches on TITLE and both were the same episode. The playlist now emits `&ih=<infohash>` and `handle_vlc_stream`/`handle_vlc_ready` map it back via `remap_id_by_infohash` → `pick_id_for_infohash` (pure, 5 tests). Absent from `last_search` entirely → positional fallback + warning, no worse than before.

**The play button must send the TARGET to the SEARCH, not only to the play (2026-09-04)**: `fastPlay` (▶ on Home / New-Episodes rows) searched with no target and then took `results[0]` blind — while the ranker's codec tier is target-scoped (H.264 preferred for NVENC targets, tier SKIPPED for native-HEVC vlc/phone so seeds decide). Measured on Silo S03E10: without the target #1 was a **919-seed 4.56 GB H.264**; with `target=vlc` it was a **3024-seed 2.73 GB HEVC** — 3.3× the peers and 1.7× fewer bytes, compounding into "all the sources are slow". `runSearch` had passed it since v3.19; `fastPlay` was simply missed. ⚠ **`seeds`, NOT `seeders`** — a diagnostic reading a `seeders` key that has never existed returned None for every result and produced a documented-but-false "Torrentio returns null seed counts" claim that two design arguments were built on (both corrected in-file 2026-09-04). `TorrentResult.seeds` is a `u32`, so a null is not even representable; counts come from Torrentio's `👤 <n>` title text via `parse_torrentio_title` and have been correct throughout.

**Next-episode ENQUEUE into the running VLC (2026-08-28, Fredrik's idea — supersedes porting the Chromecast queue)**: the Chromecast queue stops-then-starts; VLC does not have to. **Config**: Mac CLI hardcodes `~/.config/spela/config.toml` — `dirs::config_dir()` returns `~/Library/Application Support` on macOS, hiding user config. Same gotcha applies to any cross-platform Rust app using the `dirs` crate. spela startup WARNs on hostname `stream_host` — generic safety net for deployments without the DNAT hijack.

**reqwest TLS / aarch64 cross (2026-05-18, prod-incident)**: reqwest stays **native-tls** (default). Do NOT "unify on rustls" via `rustls-tls-*-no-provider` — with the aws-lc-rs process-default (`CryptoProvider::install_default` in `main()`) the no-provider variant fails crypto at **runtime**, silently degrading the **live server** (0 posters / 403; reverted `f08f8d6`). The build passing ≠ safe; verify the live TMDB/torrentio path. For any future Shannon aarch64 reqwest binary, native-tls→openssl-sys needs **vendored static OpenSSL** (`reqwest native-tls-vendored`), NOT a `Cross.toml` dynamic `libssl-dev:arm64` (cross-rs's old image ships OpenSSL 1.0.x → ABI-mismatches Shannon's Trixie 3.x at load). The Shannon-side Rust binary today (`spela-renderer`, see next) avoids reqwest entirely — it uses GStreamer's own HTTP source elements.

**spela-renderer on Shannon** (2026-05-29; **load-bearing pad-link bug fixed + live-verified 2026-06-09**, kiosk commit `dbcd8ca`): Rust gstreamer-rs binary in the shannon-bedroom-kiosk repo (`src/bin/spela-renderer.rs`, cross-built via `deploy-shannon-kiosk spela-renderer`). Replaces the gst-launch shell pipeline in `spela-local` v5 (presence check + soft fallback to v4 gst-launch if missing). **Until 2026-06-09 the v5 path was always failing silently** — `hlsdemux.link(&tsdemux)` static-linked dynamic-pad elements (hlsdemux source pads only materialize at runtime when the HLS playlist parser detects the muxed-TS stream variant); fix uses `connect_pad_added` mirroring the existing tsdemux→queues wiring. v5 is now THE primary Watch path; v4 retained for renderer-missing edge cases. Pipeline state transition is explicit `Paused → state(timeout=10s) → Playing` to honor the cage compositor's xdg_surface initial-configure event. Exposes a Unix-socket control IPC (`$XDG_RUNTIME_DIR/spela-renderer.sock`, line-delimited text: `seek_relative N` / `seek_absolute N` / `play_pause` / `quit`) AND an in-process `gilrs` Xbox-controller listener that applies the same commands directly to the GStreamer pipeline — closes the kiosk-Phase-4 input-during-playback architectural fork (renderer-owns-display = renderer-owns-input). HTTP source is `curlhttpsrc` (libcurl, better keep-alive than libsoup) with soft-fallback to `souphttpsrc`. Time-based 10 s queue cap smooths per-segment HLS fetch CPU spikes (Rank-8 step 2 of the HW-decode optimization arc). Residual non-fatal stderr noise (EGL_BAD_PARAMETER × 2 from gstreamer-rs EGL probing + wlr_xdg_surface chatter from waylandsink surface lifecycle) does NOT kill the pipeline. Full architecture: `~/Projects/shannon-bedroom-kiosk/CLAUDE.md` § "Controller-during-playback architecture".
